# Support matrix: what this family adds

Story 1.6. This is a delta on Fire Temple's [support matrix](../../firetemple/docs/support-matrix.md), which covers WebGPU itself, the browsers that ship it, `rgba16float` targets, timestamp queries and the HDR canvas, and on Snow Temple's [delta](../../snowtemple/docs/support-matrix.md) (read-write storage textures, storage atomics, `float32-filterable`). This page covers only what Earth Temple leans on beyond those: the grass engine's compute-to-indirect-draw path and its multisampling.

**Checked so far:** Chrome 152 on an Apple M1 Max (Metal 3), probed on 2026-10-29 from the dev server, Chrome 156 headless (`npm run browser-check`), and Dawn under Node for the tests and studies. Safari, Firefox, Windows, Android and an integrated GPU are not checked yet; they belong to the device matrix (story 10.2). Spec facts below are from the WebGPU and WGSL specifications, not measured.

## What it means for the plan

- **Nothing in M0 needs an optional feature.** The draw arguments are written by compute and read by `drawIndirect`, which is core; `indirect-first-instance` would let one pipeline draw all three LOD lists, but an `override` offset per pipeline does the same.
- **Multisample only what is drawn.** Sample counts are 1 or 4, and 4x colour and depth over a full canvas at a high DPR are large. An effect that covers part of its canvas renders that part.
- **Writing the coverage mask has a price.** A fragment shader that writes `sample_mask` or discards cannot have its hidden fragments rejected early. It is worth it for thin far blades; story 2.7 tests whether near blades, which cover whole pixels, should be drawn by a pipeline without it.
- **The CI renderer is not the browser.** Lavapipe crashed on a texture read after a workgroup barrier (Snow Temple, 2026-10-29). The grass compute shaders have no barriers.
